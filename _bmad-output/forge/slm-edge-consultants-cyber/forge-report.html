Assistant d'audit local pour consultants cyber

Session Forge Idea · 2026-10-17 · Anaël

Idée de départ : un SLM on-edge (16 Go, sans GPU, sans cloud) pour le pool audit de Wavestone.

Verdict

L'idée tient, mais reformulée. Le produit n'est pas « un SLM bureautique ». C'est une application d'assistance à l'audit au moteur interchangeable, qui commence par les fiches de vulnérabilité : on retrouve le constat type dans un catalogue, puis on l'adapte aux notes du consultant. La justification du local est l'interdiction de sortir les données client (PASSI, contrats). L'absence d'Internet n'en est pas une.

Décisions verrouillées

  • Le moteur passe par un endpoint compatible OpenAI : un SLM local aujourd'hui, un LLM interne Wavestone demain s'il est construit.
  • Le fine-tuning est une R&D personnelle séparée, hors chemin critique.
  • Filtre : uniquement les tâches portant sur des données client.
  • Cas n°1 : fiches de vulnérabilité, traitées par lot et non en chat. Cas n°2 : scripts d'analyse des sorties d'outils.
  • POC sur un gabarit générique et des données publiques, puis entrants des collègues et sponsor, puis pilote réel.
  • POC vérifiablement hors ligne (test, SBOM, SHA-256 des poids), données synthétiques seulement, périmètre figé (FR, sortie Word).
  • Distribution par un dépôt GitHub et uv sync. Charte visuelle Wavestone ; format générique Description / Impact / Recommandation / CVSS 3.1 / Références.
  • Extension n°2 : CERT et réponse à incident, prévue dans l'architecture.

Rejeté, et pourquoi

  • Assistant bureautique générique : il existe déjà un contournement (ChatGPT sur le téléphone), et Copilot le rendra caduc.
  • Chat interactif : inutilisable à 1,3 token/s (mesure sur l'EliteBook).
  • SLM fine-tuné au cœur du produit : coûteux, et périssable face à un LLM interne de 30 à 70 milliards de paramètres.
  • Génération d'exploits : les SLM alignés refusent, et les modèles débridés posent un risque de supply chain.

Points faibles qui ont survécu

  • Le besoin est connu par ouï-dire. Il reste trois questions d'entretien : la frontière exacte, le poids des fiches dans une mission, la chaîne de rédaction et l'existence d'un catalogue.
  • Un LLM interne cloisonné reste possible : l'avantage du local a peut-être une durée de vie limitée.
  • Installation : accès à PyPI, GitHub et HF depuis le poste ; moteur Windows sans compilateur.
  • Charte Wavestone dans un dépôt public : il faut un accord de la communication.
  • Risque de dispersion avec six dépôts actifs.
