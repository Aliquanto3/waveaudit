- (direction) Levée du non-goal CERT par l'utilisateur le 2026-10-17 : à développer après le MVP, la validation SLM et le durcissement.
- (decision) Sources V1 : événements Windows (Security, Sysmon) exportés en CSV ou JSON ; Linux auth.log / syslog / secure en texte. Pas d'EVTX binaire ni de journaux web.
- (decision) Détection déterministe par un catalogue de règles YAML inspiré de Sigma, chacune avec un texte type ; le SLM n'adapte que le récit ; aucun indicateur inventé.
- (decision) Rapport Word complet : synthèse, chronologie, faits détectés (récit, preuves), indicateurs de compromission extraits par le code, actifs touchés, recommandations, bandeau démonstration.
- (decision) Le workflow incident a son propre service applicatif (éléments et rapport différents des fiches) ; il partage le port Moteur, la composition, le garde réseau, les événements de lot et les conventions (AD-17).
- (constraint) Mêmes contraintes que SPEC-waveaudit-poc : hors ligne, données fictives, SLM < 2B, moteur interchangeable, Windows sans admin.
- (note) Non-goals V1 : EVTX binaire, journaux web, UI web pour le CERT, corrélation multi-sources avancée, enrichissement par réseau (réputation IP, VirusTotal).
- (decision) Stories C1 à C6 (socle CERT, journaux + démo, règles + détection, indicateurs + garde-fous, workflow + service + calibrage, rapport + CLI) ; vagues M à P du plan de nuit.
- (event) Self-validate : 7 capacités avec intent et success automatisables, 4 contraintes, 4 non-goals ; formes exactes dans contrats §21.
