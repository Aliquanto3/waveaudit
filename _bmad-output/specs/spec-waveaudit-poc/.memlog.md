- (note) Source : forged-idea.md (issue HARDENED, 2026-10-17) ; décisions verrouillées reprises telles quelles.
- (decision) Moteur d'inférence : llama-server (llama.cpp) épinglé, binaire et poids vérifiés par SHA-256, appelé via API compatible OpenAI (choix utilisateur 2026-10-17).
- (decision) Tests : faux serveur OpenAI déterministe pour unitaires et E2E ; un seul test réel marqué slow, sauté si les poids sont absents (choix utilisateur).
- (decision) Interface : CLI par lot + petite UI locale qui pilote le même noyau que la CLI (choix utilisateur).
- (direction) Développement autonome de nuit par la chaîne agent-cost-kit : chaque critère d'acceptation doit être vérifiable automatiquement, sans humain ni vrai modèle.
- (capability) CAP-1 Import d'un dossier de notes brutes (un fichier par constat) ; note invalide signalée sans arrêter le lot.
- (capability) CAP-2 Catalogue de constats types en FR, rédigé à partir de sources publiques (CWE, OWASP WSTG, ANSSI), chaque entrée avec références vérifiables.
- (capability) CAP-3 Recherche du constat type le plus proche d'une note dans le catalogue (RAG), candidats classés.
- (capability) CAP-4 Adaptation du constat type aux notes via le moteur : fiche Description / Impact / Recommandation / CVSS 3.1 / Références ; sortie invalide du modèle -> nouvel essai puis repli marqué « à revoir ».
- (capability) CAP-5 Garde-fous déterministes : références limitées au catalogue (toute référence inventée retirée et signalée), score CVSS calculé par le code depuis un vecteur validé.
- (capability) CAP-6 Export Word : un rapport .docx, une fiche par constat, bandeau « démonstration », thème générique ; thème privé optionnel lu depuis theme-prive/.
- (capability) CAP-7 CLI par lot : dossier de notes -> rapport .docx, progression et journal par fiche, code retour significatif.
- (capability) CAP-8 UI locale : déposer des notes, lancer le lot, suivre l'avancement, télécharger le .docx ; écoute sur 127.0.0.1 seulement.
- (capability) CAP-9 Moteur interchangeable : endpoint, modèle et paramètres changés par configuration seule (SLM local maintenant, LLM interne plus tard).
- (capability) CAP-10 Installation vérifiable : récupération de llama-server et des poids épinglés avec contrôle SHA-256, refus en cas d'écart, source documentée.
- (capability) CAP-11 Preuve hors ligne : test automatisé qui échoue sur tout appel sortant hors boucle locale pendant un lot ; SBOM généré.
- (capability) CAP-12 Banc de mesure : temps par fiche et pic mémoire sur le vrai moteur, rapport lisible.
- (constraint) Aucun appel réseau sortant à l'exécution (loopback seul) ; téléchargements uniquement à l'installation.
- (constraint) Données publiques ou fictives seulement ; bandeau « démonstration » sur toute sortie.
- (constraint) Jamais de génération ex nihilo : toute fiche part d'un constat type du catalogue.
- (constraint) Cible : Windows 11, CPU seul, 16 Go avec Office ouvert, sans droits admin ni compilateur ; Python 3.12 via uv ; pic mémoire total <= 6 Go.
- (constraint) Moteur appelé uniquement via l'API compatible OpenAI ; aucun couplage au moteur local dans le code métier.
- (constraint) Charte et logo Wavestone hors dépôt public (theme-prive/ ignoré par git) ; le dépôt fonctionne sans eux.
- (constraint) Distribution par git clone + uv sync, dépendances épinglées (uv.lock) ; périmètre figé : notes -> fiche, FR, sortie Word.
- (constraint) Traitement par lot, jamais en chat : débit 1,3-5,7 tok/s sur la machine cible.
- (constraint) L'architecture accueille un second workflow (CERT / réponse à incident : parseurs de logs, gabarit de rapport) sans refonte ; il n'est pas développé.
- (assumption) Format des notes : un fichier .md ou .txt par constat, en-tête YAML optionnel (titre, actif, sévérité pressentie), corps libre avec preuves en texte.
- (assumption) Catalogue : 30 à 50 constats rédigés en propre dans le dépôt (pas de copie de texte sous CC BY-SA), citant identifiants et URL publiques (CWE, WSTG, ANSSI).
- (assumption) Modèle par défaut : SLM instruct 3-4B, GGUF Q4, licence permissive (ex. Qwen3-4B-Instruct, Apache 2.0) ; choix final hors nuit via slm-quality-bench.
- (assumption) Les 20 notes fictives de démonstration sont rédigées dans le dépôt, chacune étiquetée de son constat type attendu.
- (assumption) La qualité perçue (>= 70 % utilisables), la vitesse et la mémoire réelles sont jugées hors nuit, sur l'EliteBook et par les collègues.
- (question) Entretien collègues : frontière exacte (PASSI interne ou poste seul), poids réel des fiches, chaîne de rédaction et catalogue existant. Non bloquant pour le POC.
- (question) Accès PyPI, GitHub et Hugging Face depuis le poste ; faut-il une variante archive des poids ? Non bloquant pour la nuit.
- (question) Accord de la communication pour la charte Wavestone. Non bloquant (thème hors dépôt).
- (note) Non-goals : chat ; fine-tuning ; génération d'exploits ; assistant bureautique générique ; anglais ; CERT et cas n°2 (code) développés ; import de formats d'outils (Burp, Nessus) ; édition de fiche dans l'UI ; multi-utilisateur ; données client réelles.
